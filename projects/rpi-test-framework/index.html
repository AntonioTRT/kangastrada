RPI Test Framework

A practical test harness for repeating embedded-device commands and capturing communication evidence.

Problem

Make DUT checks repeatable.

Manual command checks are difficult to repeat and compare. This framework runs commands against a DUT and captures serial responses and I2C activity around selected tests.

My contribution

Connect command execution with lab evidence.

I built Python test modules that load per-test YAML settings, invoke the DUT command utility, compare responses with expected values, and record TX/RX data to CSV. The I2C capture path controls a Tektronix scope, decodes its event export, and stores the transactions alongside the test run.

Validation

Check responses and preserve evidence.

The command-list test supports exact, contains, and numeric-range checks. Loop tests save command/response logs and decoded I2C transaction data. This documents the implemented validation path, not a particular pass rate or product qualification result.

Outcome

Reusable test and capture components.

The repository provides focused command, listen, and scope-capture utilities. The top-level runner still needs alignment with the per-test configuration before it can serve as a streamlined selectable test suite.
