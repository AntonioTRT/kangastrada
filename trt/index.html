TRT embedded runtime

A shared firmware and command-line path for discovering and communicating with embedded boards.

Problem

Make board communication consistent.

Embedded projects often develop their own command and discovery paths. TRT brings a host CLI, a common protocol, and reusable firmware components together while leaving each board responsible for its hardware.

My contribution

Build the path from CLI to board.

I developed the Python CLI and a portable C++ runtime with protocol parsing, command dispatch, capability reporting, and board-level interfaces. The runtime uses a cooperative loop so local board behavior does not depend on host traffic.

Board integrations provide transport and hardware-specific behavior. The simulator and Arduino adapter exercise the shared contracts; STM32 integration remains separate work.

Validation

A real serial transaction on Arduino Uno.

The CLI communicated with an Arduino Uno running TRT firmware over COM4. The board-info workflow returned board ID 101, firmware version 0.1.0, and build ID 000004.

Outcome

A verified starting point for board tooling.

The Arduino transaction demonstrates the end-to-end host-to-firmware path on one target. It does not mean every planned board, peripheral command, or transport is implemented.
